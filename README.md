# HFT market maker — Binance USDⓈ-M

Маркет-мейкер для бессрочных фьючерсов Binance. Код новой версии — в `mm/`,
старая версия бота сохранена в `legacy/`.

## Быстрый старт

```bash
pip install -r requirements.txt

python main.py --scan                       # рейтинг монет прямо сейчас
python main.py                              # бумажная торговля (по умолчанию)
python main.py --symbols DOGEUSDT           # бумажная торговля на одной монете
python main.py --live                       # реальная торговля
python -m pytest tests -q                   # тесты (офлайн)
```

Для `--live` создайте `key.env` в корне:

```
BINANCE_API_KEY=...
BINANCE_API_SECRET=...
BINANCE_TESTNET=false
```

Логи и результаты пишутся в `logs/`: `bot.log`, `pnl_<mode>.csv`,
`fills_<mode>.csv` (каждое исполнение с markout через 1/5/30 с).

## Стратегия

Маркет-мейкер зарабатывает на разнице между ценой покупки и продажи и теряет,
когда цена уходит против взятой позиции (adverse selection). Прибыль есть,
только если на одно исполнение `заработанный полуспред − adverse − комиссия > 0`.
Каждый этап ниже работает на это неравенство.

### 1. Отбор монеты (`mm/scanner.py`)

| Фильтр | Почему |
|---|---|
| Объём 24ч: $30M–$1.5B | Снизу — нужны исполнения. Сверху — на топ-монетах спред 1 тик, а очередь у лучшей цены занимают колоцированные HFT с задержкой ~1 мс. С 65 мс там не выиграть |
| Изменение за 24ч ≤ 25% | Памп/дамп = тренд, а тренд съедает спред. Старый бот выбирал именно такие монеты — главная причина убытков |
| Тренд за час ≤ 0.35 | efficiency ratio по 1m свечам: 0 — пила, 1 — чистый тренд |
| Медианный спред ≥ 3 bps | Должно быть что зарабатывать после комиссии 2 bps |
| ≥ 30 сделок в минуту | Иначе заявки почти не исполняются |
| σ 1m ≤ 35 bps | Высокая волатильность = большой adverse |
| \|funding\| ≤ 0.05% | Не платить за удержание |

Оценка: `net = spread/2 − maker_fee − 0.1·σ_1m`, `score = net · √(сделок/мин)`.
Каждые 15 мин рынок пересканируется. Монета меняется, если новая лучше на 30%
и по текущей нет позиции.

### 2. Справедливая цена (`mm/strategy.py`)

`fair = mid · (1 + alpha)`, где alpha (не больше ±4 bps) складывается из:
- **microprice** — смещение mid к стороне с меньшим объёмом на лучшем уровне;
- **дисбаланса 5 уровней стакана**;
- **потока агрессивных сделок** (EWMA, полураспад 2 с).

Заявки ставятся вокруг прогноза, а не вокруг текущего mid. Так нас реже
«переезжают» перед движением.

### 3. Ширина котировки

```
полуспред = max( комиссия + мин. прибыль + измеренный adverse,   ← не работать в минус
                 σ_1s · √2с )                                    ← движение за время реакции
```

Measured adverse — это EWMA ухода mid против нас через 5 с после
исполнения. Бот сам расширяет спред, если его «переезжают». При задержке
> 250 мс спред ×1.5. Сверху ограничен 40 bps.

### 4. Управление позицией

- **Сдвиг котировок (skew):** при лонге обе цены сдвигаются вниз (до 6 bps при
  полной позиции, плюс 3 bps за каждую минуту удержания). Бот охотнее
  продаёт и неохотнее докупает.
- **Размер:** заявка на вход уменьшается по мере роста позиции и пропадает
  при `max_inventory_usdt`.
- **Выход:** одна reduceOnly-заявка на весь объём позиции. Первые 30 с —
  не дешевле `вход + 2·комиссия + 1 bps`, дальше — по рыночной логике
  со сдвигом.
- **Все заявки post-only (GTX):** платим только комиссию мейкера.
- **Перекотировка** — только если цена ушла ≥ 1 bps (или ≥ 1 тик). Так заявка
  сохраняет место в очереди и не тратятся лимиты API. Старый бот снимал и
  ставил сетку каждые 0.5 с.

### 5. Закрытие и стопы (`mm/bot.py`)

| Условие | Действие |
|---|---|
| Цена ушла на 35 bps против входа | выход по рынку, пауза входов 10 с |
| Позиция держится > 180 с | выход по рынку |
| Спред > 4× медианы или σ > 4× базовой | пауза входов 20 с |
| BTC сдвинулся на 40 bps за 3 с | пауза входов по всем монетам |
| Средний markout за 40 fills < −1 bps | монета токсична: пауза 10 мин, ротация |
| Убыток по монете > $1.5 | ротация |
| 30 с до funding | без новых входов |
| Убыток сессии > 5% баланса | остановка бота, закрытие позиций |

### 6. Оценка прибыльности: markout

Каждое исполнение пишется в `logs/fills_*.csv` вместе с ценой mid через
1, 5 и 30 секунд. `markout_5s − fee_bps` — чистый результат исполнения:

- **в среднем > 0** — стратегия зарабатывает на этой монете;
- **< 0** — нас «переезжают»: нужно расширять спред или менять монету.

Это главный показатель. Итоговый P&L за короткий период слишком шумный.

## Задержка и VPS

Матчинг Binance находится в AWS Tokyo (ap-northeast-1). С VPS в Гонконге
задержка ~65 мс, из Токио — 1–5 мс. **Переезд на VPS в Токио — самое сильное
улучшение для маркет-мейкера.** Стратегия рассчитана на 65 мс:
- торгуем монеты с широким спредом, где приоритет даёт улучшение цены, а не скорость;
- не гоняемся за каждым тиком (порог перекотировки);
- спред включает движение цены за время реакции (`vol_horizon_s`).

Значение задержки нужно указать в `PaperConfig.latency_ms`.

## Порядок запуска

1. `python main.py --scan`: убедиться, что сканер находит монеты.
2. `python main.py` (paper) **минимум 24–48 часов**. Смотреть в `logs/`:
   - средний `markout_5s − fee_bps` в `fills_paper.csv` > 0;
   - net P&L в `pnl_paper.csv` растёт;
   - число стопов в `bot.log` (`🛑`) небольшое.

   Paper-модель консервативна: заявка исполняется, только если сделка прошла
   *сквозь* её цену. В реальности исполнений будет больше, но больше будет и adverse.
3. Live с минимальным размером (`--order-usdt 6 --max-inventory-usdt 12`),
   сравнить markout live и paper.
4. Увеличивать размер, только если live markout стабильно положительный.

## Комиссии

Ключевой параметр — `ExchangeConfig.maker_fee_bps` (VIP0 = 2 bps).
При VIP-уровне, скидке BNB или ребейте мейкера порог прибыльности резко
снижается. Указывайте свои фактические комиссии.
